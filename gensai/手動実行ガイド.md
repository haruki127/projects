# 手動実行ガイド — 自分の PC でパイプラインを動かす

このシステムを Cowork や Claude 経由ではなく、自分の PowerShell から直接
動かす手順です。Windows 11 + Python 3.10 以上が前提です。

**プロジェクトの場所**: `D:\projects\gensai\las_diff_pipeline\`

ドライブと大文字小文字に注意してください。`D:\Projects` ではなく `D:\projects`、
プロジェクトフォルダは `gensai`、その中に `las_diff_pipeline` があります。

```
D:\projects\
└── gensai\
    ├── .gitignore
    ├── 手動実行ガイド.md        ← 本ファイル
    └── las_diff_pipeline\
        ├── main.py
        ├── config.example.yaml
        ├── requirements.txt
        ├── README.md
        ├── pipeline\           # コアモジュール
        ├── examples\           # 合成データ / 実データ用スクリプト
        └── viewer\             # ブラウザ用 HTML
```

## STEP 0. 前提確認

Python が入っているか確認:

```powershell
python --version
```

→ `Python 3.10.x` 以上が出れば OK。出ない場合は <https://www.python.org/downloads/>
からインストールしてください（**「Add python.exe to PATH」にチェック必須**）。

## STEP 1. プロジェクトフォルダに移動

```powershell
cd D:\projects\gensai\las_diff_pipeline
```

## STEP 2. 依存ライブラリのインストール

### 2-1. 仮想環境を作る（プロジェクト専用の Python 環境）

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

PowerShell で「スクリプトの実行が無効」エラーが出る場合:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

を一度だけ実行し、再度 `Activate.ps1` を試してください。
仮想環境を有効化すると、プロンプトの先頭に `(.venv)` が表示されます。

### 2-2. パッケージインストール

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

数分かかります。Open3D が入らない場合は `requirements.txt` の `open3d>=0.18`
を一時的にコメントアウト（`#`）して再実行してください。ICP は **scipy 自前
実装が自動でフォールバック**するので Open3D 無しでも全機能使えます。

- 不透明度スライダ: 背景写真とのバランス調整

## STEP 6. 別のデータで一般的に動かす

`config` YAML を書いて `main.py` に渡すのが本筋です。
`examples\config_synthetic_no_open3d.yaml` をコピーして編集:

```yaml
io:
  pre_las: "D:/path/to/pre.las"
  post_las: "D:/path/to/post.las"
  output_dir: "D:/path/to/output"

crs:
  input_epsg: 6675     # データの座標系
  output_epsg: 4326    # 出力は WGS84 固定
  work_epsg: 6675

preprocess:
  bbox: [minx, miny, maxx, maxy]   # 必要なら切り出し
  voxel_size: 0.5                  # 大規模なら間引き

registration:
  enabled: true                    # ICP 有効化

difference:
  method: "dsm"
  dsm:
    resolution: 0.5
    method: "max"                  # 屋根を見るなら max、地表は min

scoring:
  thresholds: [0.3, 1.0, 3.0]

aggregation:
  unit: "grid"
  grid:
    cell_size: 5.0
```

実行:

```powershell
python main.py --config path\to\your_config.yaml -v
```

`--step preprocess|registration|difference` で部分実行も可能。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| `python が見つからない` | Python インストール時に PATH に追加されていない。再インストールで「Add to PATH」チェック |
| `pip install` で `Microsoft Visual C++ 14.0 is required` | <https://visualstudio.microsoft.com/visual-cpp-build-tools/> から Build Tools をインストール |
| `geopandas` / `rasterio` で wheel エラー | Python 3.11 などに切り替え、または `pip install --only-binary=:all: geopandas rasterio` |
| `open3d` インストール失敗 | 諦めて該当行をコメントアウト → scipy フォールバックが効く |
| ブラウザでマップが真っ白 | F12 で Console を確認。CORS エラーなら `python -m http.server` で配信しているか確認 |
| GeoJSON が読まれない | `viewer\` フォルダにファイルがあるか確認。なければ「ファイル選択」ボタンから手動指定 |
| ICP が遅い / 終わらない | `registration.enabled: false` にして無効化、または `voxel_size` を大きく (0.5→1.0m) |
| メモリ不足 | `preprocess.bbox` で範囲を絞る、`voxel_size` を大きくする |
| `Operation not permitted` (ファイル削除) | Windows のファイルロック。エクスプローラーで削除するか OS 再起動後に削除 |

## よくある質問

### Q. 仮想環境を使わずグローバルに入れていい？
A. 可能ですが、他のプロジェクトと依存関係が衝突しがちなので venv 推奨です。
グローバルに入れる場合は `pip install --user -r requirements.txt`。

### Q. データの座標系がわからない
A. 次のコマンドで確認できます:
```powershell
python -c "import laspy; print(laspy.open('your.las').header.parse_crs())"
```

### Q. 大規模データで重い
A. 順に試してください:
1. `preprocess.bbox` で範囲を絞る
2. `preprocess.voxel_size` を大きく (0.5→1.0→2.0m)
3. `difference.dsm.resolution` を粗く (0.5→1.0→2.0m)
4. `aggregation.grid.cell_size` を大きく (5→10→20m)
5. ICP を `registration.enabled: false` で無効化

### Q. 結果が想定と違う
A. 以下を確認:
- PRE / POST の座標系が一致しているか
- ジオイド高補正の必要性（標高 vs 楕円体高で 30〜40m ずれることがある）
- PRE と POST の点の意味（全点 / ground filtered）が揃っているか
- DSM method (`max` vs `min`) がデータに合っているか

### Q. github にアップしたい
A. `.gitignore` を `D:\projects\gensai\.gitignore` に同梱しています
（`.venv`, `__pycache__`, `*.las`, `outputs/` などを除外）。
```powershell
cd D:\projects\gensai
git init
git add .
git commit -m "initial"
```
で開始できます。大容量 LAS は除外されているので、データは別途配置してください。

### Q. パスを別の場所に変えたい
A. プロジェクトをフォルダごと移動した後、以下を編集:
- `examples\run_realdata.py` の `OUT_DIR`（既定: `D:\projects\gensai\...`）
- 各 YAML の `output_dir`（既定: 相対パス、安全）

YAML 内のパスは config 相対のため、フォルダ移動だけなら基本そのままで動きます。

## 既知バグと修正履歴 (2026-06)

実際に発生したバグと修正内容のメモです。同様の症状が出たときの参考にしてください。

---

### Bug 1 — `run_realdata.py` が即クラッシュする (`FileNotFoundError`)

**症状:**

```
FileNotFoundError: [Errno 2] No such file or directory: 'D:\\notowest14\\07FD2032.las'
```

**原因:** スクリプト内のパスが古い場所を指していた。データは `D:\projects\` 配下に移動済み。

**修正箇所:** `examples\run_realdata.py` 先頭の 2 行

```python
# 修正前（誤）
PRE  = r"D:\notowest14\07FD2032.las"
POST = r"D:\ground_data_07fd1_2025\07fd203_grd.las"

# 修正後（正）
PRE  = r"D:\projects\notowest14\07FD2032.las"
POST = r"D:\projects\ground_data_07fd1_2025\07fd203_grd.las"
```

---

### Bug 2 — ボクセル間引き・地表抽出でまれに点が誤合算される

**症状:** 見た目では分かりにくいが、大規模データ（数十万点以上）で
グリッドの統計値がわずかにおかしい、または合成データでも再現性がない。

**原因:** `pipeline/preprocess.py` の `voxel_downsample` と `classify_ground` が
XOR ベースのハッシュキーでボクセルを識別していた。
`ix=19349663, iy=0` と `ix=0, iy=73856093` のような組み合わせで
異なるボクセルが**同じキーに衝突**し、無関係な点が同じグループに混入していた。

```python
# 旧実装（衝突あり）
key = ix[:, 0] * 73856093 ^ ix[:, 1] * 19349663 ^ ix[:, 2] * 83492791
```

**修正内容:** `np.lexsort` による辞書順ソートに変更（衝突ゼロ、ループも排除）。

```python
# 新実装（衝突なし）
order = np.lexsort((ix[:, 2], ix[:, 1], ix[:, 0]))
```

**`classify_ground` も同様**に `np.lexsort((xyz[:, 2], iy, ix))` で
「同セル内を Z 昇順ソート → 先頭が min-Z 点」という構造に変更。

---

### Bug 3 — スコアが全体的に高めになる（score 2 が異常に多い）

**症状:** 能登半島の実データで score 2 が 64% を超え、目視確認と乖離する。

**原因:** `pipeline/aggregation.py` の `aggregate_grid` が
`dz_mean`（セル内平均）ではなく `dz_p95`（|dz| の 95 パーセンタイル）で
スコアを計算していた。セル内に数点の外れ値があるだけで
スコアが最大値まで跳ね上がる。

```python
# 旧実装（dz_p95 基準 → 外れ値に過敏）
score = int(score_by_thresholds(np.array([dz_p95]), thresholds)[0])

# 修正後（dz_mean 基準 → run_realdata.py・建物スコアと一致）
score = int(score_by_thresholds(np.array([dz_mean]), thresholds)[0])
```

> `dz_p95` は引き続き GeoJSON プロパティとして出力・記録されます。
> 確認用統計として参照してください。

---

### Bug 4 — DSM method が "max" のまま → 全セルが大きな負 dz になる

**症状:** `main.py` 経由でパイプラインを動かすと、ほぼ全セルが
`dz_mean ≈ -10m` 以下になり score 3 が大量発生する。

**原因:** `examples/config_realdata_osm.yaml` の DSM method が `"max"` のままだった。
POST が**地表フィルタ済み**（グランドデータのみ）の場合、
- `max(PRE)` ＝ 建物の屋根・樹冠の最高点
- `max(POST)` ＝ 地表

を比較してしまうため、建物があった場所が全て「崩壊」と誤判定される。

**修正箇所:** `examples/config_realdata_osm.yaml`

```yaml
# 修正後（POST が地表フィルタ済みのときは "min"）
difference:
  method: "dsm"
  dsm:
    resolution: 0.5
    method: "min"   # ← "max" から変更
```

> **覚え方:** POST が全点データ（ドローン SfM など）なら `"max"` でも可。
> POST が地表のみ（ground filtered）なら必ず `"min"` にすること。

---

### Bug 5 — M3C2 の LoD95 有意性が最終スコアに効いていない

**症状:** `use_significance: true` + M3C2 モードにしても、
有意でない点のスコアが下がらない。

**原因:** `main.py` の Step 5 で `apply_significance` を使って
`prelim_score` を補正していたが、その後の集約関数
（`aggregate_grid` / `aggregate_buildings`）が**独自にスコアを再計算**するため、
補正された `prelim_score` は捨てられていた。
`significant` マスク（有意フラグ配列）のみが集約関数に渡され正しく使われる。

**修正内容:** `prelim_score` の無駄な計算を削除し、
`significant` マスクだけを構築するように整理。

```python
# 修正後（main.py Step 5）
if use_sig and lod95 is not None:
    _, significant = apply_significance(dz, lod95, np.zeros_like(dz, dtype=np.int8))
else:
    significant = None
```

> M3C2 はまだ stub 実装（`NotImplementedError`）のため、
> 現状は DSM モードのみ有効。lod95 が None になるので
> このバグが実害になるのは M3C2 を実装した後です。
